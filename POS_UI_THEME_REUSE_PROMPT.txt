PROMPT: APPLY THIS POS DASHBOARD AND TRANSACTION UI THEME
=========================================================

The POS application already exists. Work inside its current codebase and
restyle its existing UI using the visual direction below. Do not create,
scaffold, or replace the application. First inspect the project structure, UI
framework, shared layouts, existing design tokens, and relevant existing
pages. Then implement the theme consistently within the current architecture.

Apply the theme to:
- The top menubar / header and its icons.
- Dashboard page and summary metric cards.
- Insights / analytics page and chart cards.
- Purchase and sales invoice-entry pages and their cards/panels.
- Sales list page, including a filter-aware Total Sales summary card above
  the sales table.
- Delivery Verification page, including its focused barcode/code-entry card.
- Report landing pages, report summary cards, filters, and report tables.
- The left navigation sidebar, its menu icons, submenus, and active states.

Do not copy source code, framework-specific templates, routes, or business
logic from another application. Recreate the appearance using this project's
existing framework and components.


VISUAL DIRECTION
----------------
Create a clean, modern business application: calm, readable, and professional.
Use a light workspace with teal as the primary brand color, blue-gray neutrals,
soft tinted cards, modest borders, rounded corners, subtle shadows, and small
hover/focus transitions. Keep the interface information-dense enough for POS
work while avoiding visual clutter.

Use these colors as the starting palette; define them as shared theme tokens
where the project supports design variables:

- Brand teal:             #0F766E
- Deep teal:              #0B5F59
- Dark teal hover:        #0C5F58
- Secondary teal:         #126B72
- Pale teal surface:      #E8F4F2
- Active teal surface:    #DFF1EE
- Page background:        #F5F7FA
- Primary surface:        #FFFFFF
- Soft card gradient:     #F8FAFC to #EEF2FF
- Main text:              #1F2937
- Secondary text:         #6B7280
- Border:                 #CBD5E1
- Light border:           #E5E7EB
- Blue metric accent:     #2A3F79
- Green metric accent:    #17643F
- Warm/orange accent:     #8A4520
- Inventory teal accent:  #0F766E

Use the teal palette for navigation, actions, selected states, and highlights.
Use blue, green, warm orange, and teal accents to distinguish dashboard metric
categories, not as competing brand colors. Keep danger, warning, and success
states semantically clear and accessible.


TOP MENUBAR / HEADER
--------------------
- Use a full-width deep teal-to-teal gradient, approximately:
  linear-gradient(105deg, #0B5F59 0%, #0F766E 58%, #126B72 100%).
- Add a subtle lower border and restrained shadow to separate the header from
  the page without making it visually heavy.
- Keep the logo legible in a neat, light rounded container if it needs a
  contrasting background.
- Style menu toggle, quick actions, notification, and profile controls as
  compact rounded squares/circles with translucent white borders and fills.
- Use white icons and clear hover/focus feedback: slightly brighter
  translucent background and a small lift at most.
- Keep icon sizing and alignment consistent. Use the target project's existing
  icon library; prefer simple outline icons over mixed icon styles.
- Keep account dropdowns white with a light border, rounded corners, subtle
  shadow, dark readable text, and pale teal hover states.
- At tablet/mobile widths, preserve essential actions and allow sensible
  wrapping or horizontal scrolling; do not let the header overflow the screen.


SIDEBAR AND MENU ICONS
---------------------
- Use a light vertical gradient, approximately #F8FBFF to #F2F7F7, with a
  subtle border and soft shadow against the content area.
- Group navigation using small uppercase or letter-spaced section labels in
  muted blue-gray.
- Use consistent menu row heights (about 44px), compact spacing, rounded
  corners (about 8px), and medium-weight labels.
- Align icons in a fixed-width column so labels line up. Use muted teal-gray
  icons at rest and brand teal on hover/active.
- Hover state: pale teal background, teal label/icon, and a light border.
- Active state: stronger pale teal fill (#DFF1EE), teal/dark-teal text and
  icon, subtle border, and a very soft shadow. Make expanded parent sections
  visually clear without making every submenu item look selected.
- Indent submenus consistently and use a subtle vertical guide line.
- Keep collapsed tooltips and mobile drawer states readable and keyboard
  accessible. Preserve permission-based visibility and existing navigation.


DASHBOARD PAGE
--------------
- Maintain a clear page title and optional breadcrumb using dark readable text
  on the light workspace.
- Organize key metrics into named groups such as Finance and Inventory.
- Give metric groups a very light blue-gray shell, subtle border, rounded
  corners (about 16-18px), and a restrained shadow.
- Use distinct metric card tints and accents:
  * Trade / sales / purchases: pale blue with dark blue accent (#2A3F79).
  * Cash: pale green with green accent (#17643F).
  * Balances / expenses / credit: pale warm tint with warm accent (#8A4520).
  * Stock / inventory: pale teal with teal accent (#0F766E).
- Metric cards should be compact, evenly sized, and easy to scan. Use a small
  uppercase or short label, a strong tabular-number value, and a simple icon
  inside a light translucent badge.
- Keep card borders coordinated with their accent at low opacity. Use subtle
  hover lift (around 2px) and soft shadow increase; no dramatic motion or
  glossy sweep effects.
- Use responsive columns that collapse cleanly on mobile. Keep titles,
  values, and icon badges from colliding at narrow widths.
- Use clean white/light surface cards for dashboard charts, notices, and
  widgets, with consistent title treatment and spacing.


INSIGHTS / ANALYTICS PAGE
-------------------------
- Present charts in consistent cards on the same light workspace.
- Use soft blue-gray gradient surfaces (#F8FAFC to #EEF2FF), a light
  blue-gray border, 12px rounded corners, and subtle shadow.
- Use bold dark chart titles, clear spacing, and a white or translucent-white
  chart plotting area with rounded corners where appropriate.
- Keep explanatory captions beneath charts small but readable and muted.
- Align paired charts in a responsive two-column layout on wide screens and
  stack them on smaller screens. Use consistent chart heights within a row.
- Use teal as the main series color, with coordinated blue, green, and warm
  secondary series. Maintain sufficient contrast and clear legends/labels.
- Do not alter chart data, calculations, filters, or reporting semantics as
  part of visual styling.


DELIVERY VERIFICATION PAGE
--------------------------
- Treat this as a focused single-task screen, not a general dashboard.
- Center a white verification card with a comfortable maximum width
  (approximately 680px), generous internal spacing, a thin cool-gray border,
  small rounded corners (about 7px), and a restrained shadow.
- Add a slim teal top accent border to connect the card to the brand without
  adding unnecessary decoration.
- Center a simple verification/barcode icon in a pale teal circular badge,
  followed by a clear, medium-weight dark navy title and a short muted
  explanatory subtitle.
- Make the code input the primary focal point: wide, tall (about 56px),
  centered uppercase text, clear placeholder, and a visible teal focus ring.
- Place camera/scan and verify actions alongside the input on desktop.
  Keep actions the same height as the input; use solid teal for the primary
  verification action and a secondary treatment for scan/camera controls.
- On mobile, place the input above appropriately sized side-by-side actions;
  maintain comfortable gaps and prevent horizontal overflow.
- Show scan preview and verification result messages within the card flow,
  with readable status feedback. Use red styling only for an explicit
  stop/cancel-camera control or error state.
- Keep the page minimal so users can quickly scan or enter a code. Preserve
  verification behavior, camera/scanner handling, and all result states.


PURCHASE AND SALES INVOICE PAGES
--------------------------------
- Make the product-entry area, invoice item table, customer/supplier details,
  and payment/summary areas easy to understand as distinct sections.
- Use light cards with subtle blue-gray borders, soft shadows, 12-15px
  corners, and a pale blue-gray panel tint for grouped sections.
- Use a concise teal-accented card header and consistent section spacing.
- Keep product lookup, barcode/camera controls, quantity/price inputs, and
  add-item actions visually grouped and prominent without overpowering the
  invoice itself.
- Make invoice totals visually distinct. Emphasize the grand total with
  stronger text and a restrained teal or pale teal treatment; maintain clear
  separation among subtotal, taxes, discount, paid amount, and balance due.
- Keep payment status choices, customer/supplier selection, and submit
  actions easy to find. Use the brand teal for primary actions and neutral
  or semantic colors for secondary/danger actions.
- Style form focus states with a teal border and a soft teal focus ring.
  Preserve visible validation errors and keyboard focus indicators.
- Avoid sweeping hover overlays or large card animations on data-entry
  screens; interactions must remain stable while scanning or editing items.
- Make tables scroll or adapt on narrow screens without hiding totals or
  critical actions. Preserve all invoice calculations and validation behavior.


SALES LIST: TOTAL SALES SUMMARY CARD
------------------------------------
- Place a compact Total Sales card above the sales table, aligned with the
  table content and responsive on small screens.
- Use a clean white/light surface, subtle border, small rounded corners, and
  restrained shadow consistent with report summary cards.
- Include a muted, concise label such as "Total Sales", a prominent currency
  total, and a small money/sales icon in a semantic teal/green accent. Use
  tabular numerals and allow long totals to wrap without clipping.
- Include a smaller scope caption that communicates whether the value is
  "All time" or a "Filtered total". If the signed-in user's view is
  restricted to their own records, identify that scope clearly.
- Add a short note when relevant that cancelled sales are excluded.
- The amount should load without excessive layout shift; show a graceful
  loading state, a clear unavailable/error state, and accessible live-region
  updates rather than a misleading zero.
- Keep the total synchronized with active sales-table filters and table
  search, across all matching pages, not just the visible page.
- Preserve permissions and record-visibility rules. Never broaden the total
  beyond the records the current user is allowed to see.
- Describe the figure as a sales/invoice total, not as payments received;
  keep it distinct from cash collected.


REPORT CARDS, FILTERS, AND TABLES
---------------------------------
- Use a consistent light card surface, soft blue-gray gradient, light border,
  rounded corners (about 12px), and restrained shadow for report containers.
- Place report titles and summary cards in a clear hierarchy. Summary cards
  should use white/light surfaces, concise muted labels, strong readable
  values, and optional semantic accent colors. Keep linked summary cards
  visibly interactive and keyboard accessible.
- Arrange filters in aligned responsive rows. Use consistent labels, control
  heights, and spacing. Focused inputs use the brand teal and a soft focus
  ring. Reset/filter actions should be easy to distinguish.
- Style report table headers with a light gray-blue background, dark
  semibold text, and a clear bottom border. Use comfortable cell padding,
  subtle row separators, alternating white and near-white rows, and a
  low-contrast hover state.
- Keep numeric values aligned and use tabular numerals where supported.
- Ensure pagination, export, print, and table controls use the same visual
  language and remain accessible.
- Preserve all report totals, filters, export behavior, and permissions.


BUTTONS, FORMS, AND ICONS
-------------------------
- Primary buttons use brand teal (#0F766E), white text, modest rounding, and
  a darker teal hover state (#0C5F58).
- Secondary buttons use neutral outlines or light surfaces; reserve red for
  destructive actions and retain confirmation patterns.
- Use one consistent icon family already installed in the project. Prefer
  outline icons, consistent stroke weight, and approximately 16-20px icons
  in navigation/actions; metric icons can be slightly larger.
- Icons should support the label, not replace important action text.
- Do not rely on color alone for selected, error, or status states.
- Maintain readable contrast, visible focus, semantic labels, and adequate
  touch target sizes.


IMPLEMENTATION REQUIREMENTS
---------------------------
1. Inspect the target app before editing. Identify shared layout, theme
   variables, component patterns, relevant routes/pages, and responsive
   breakpoints.
2. Implement shared tokens and reusable styles/components where practical.
   Prefer the project's existing CSS architecture and UI framework.
3. Apply the theme to every listed surface consistently, including empty,
   loading, hover, focus, active, and validation states where relevant.
4. Preserve existing business logic, navigation, labels, data, permissions,
   calculations, form submission, and report behavior. This is a visual
   redesign, not a workflow rewrite.
5. Avoid broad global selectors that unintentionally restyle modals,
   receipts, authentication pages, or unrelated components. Scope styles to
   the app shell or intended components.
6. Ensure responsive behavior at desktop, tablet, and mobile breakpoints.
7. Run the smallest relevant build, lint, or UI tests available. Report what
   changed, which pages were covered, and any checks that could not be run.

The result should feel like one cohesive POS product: a teal branded header,
light teal-aware navigation, calm blue-gray content surfaces, purposeful
metric accents, clean invoice cards, and consistent reporting UI.
